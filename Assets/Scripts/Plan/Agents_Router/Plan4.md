# Plan4: 마크다운 기반 스킬(SKILL.md) 제작 프레임워크

본 문서는 유니티 클라이언트에서 유저가 직접 생성하고 편집할 **Skill 템플릿의 구조와 제작 철학**에 집중한 설계안입니다. (오케스트레이터의 활용 로직은 배제하고, 순수하게 "스킬을 어떻게 정의하고 만들 것인가"에 집중합니다.)

---

## 1. 제작 철학 및 레퍼런스

### 1-1. Pi Framework의 급진적 미니멀리즘 (Radical Minimalism)
*   **철학**: "에이전트는 단순히 도구를 호출하는 LLM일 뿐이다."
*   **적용**: 스킬 역시 복잡한 조건문(if-else)이나 파이썬 문법을 강제하지 않습니다. 사람에게 지시하듯 작성된 아주 단순한 **자연어 텍스트**가 가장 강력하고 유연한 스킬이 됩니다.

### 1-2. OpenCode의 `SKILL.md` 패턴
*   **철학**: 모든 지식과 절차를 하나의 마크다운 파일로 캡슐화합니다.
*   **적용**: 파일 상단의 메타데이터(Frontmatter)로 기계가 스킬을 쉽게 찾게 돕고, 하단의 본문(Body)으로 LLM에게 행동 요령을 전수합니다.

### 1-3. "지금까지 한 동작을 스킬로 정리해보자"
*   유저가 매번 빈 화면에서 스킬을 타이핑하는 것은 고역입니다.
*   가장 이상적인 스킬 생성 워크플로우는: 유저가(혹은 에이전트가 수동 조작으로) 목표 달성을 위해 1~5번의 행동(클릭, 대기 등)을 성공적으로 마쳤을 때, **"방금 한 일련의 과정(Trajectory)을 바탕으로 SKILL.md를 자동 초안 작성"**해주는 기능입니다. 유저는 생성된 마크다운을 조금만 수정(CRUD)하여 저장하면 됩니다.

---

## 2. `SKILL.md` 파일의 해부학 (Anatomy)

스킬 파일은 복잡한 JSON이나 배열(`[]`)이 아닙니다. 철저히 마크다운의 구조를 따릅니다.

### 2-1. 메타데이터 영역 (YAML Frontmatter)
파일의 최상단에 `---`로 구분되어 위치하며, 시스템이 스킬을 검색하고 분류하는 데 사용됩니다.
*   `name`: 스킬의 고유한 이름
*   `description`: 스킬이 무엇을 하는지, 언제 써야 하는지에 대한 요약
*   `triggers`: 이 스킬을 발동시킬 만한 유저의 발화 키워드 목록

### 2-2. 지침 영역 (Markdown Body)
LLM이 실제로 읽고 참고할 내용입니다.
*   **`# 목표`**: 이 스킬이 달성하고자 하는 최종 상태.
*   **`# 절차`**: 순차적으로 해야 할 일. (너무 엄격한 스크립트보다는, LLM이 상황에 맞춰 판단할 수 있는 여지를 줍니다.)
*   **`# 주의사항`**: 에러가 자주 나거나 조심해야 할 부분 (선택 사항).

## 3. `SKILL.md` 구체적 예시 모음

### 예시 1: 블루아카이브 우편함 확인 (게임 UI 조작)
```markdown
---
name: "우편함 수령 스킬"
description: "로비 화면에서 우편함 아이콘을 찾아 모든 보상을 수령하는 일련의 과정입니다."
triggers: ["우편함", "보상 받기", "편지"]
---

# 목표
메인 로비 화면에서 우편함에 진입하여, '일괄 수령' 버튼을 누르고 다시 로비로 돌아온다.

# 절차
1. 화면 우측 상단의 편지 봉투 모양 아이콘(우편함)을 찾아 클릭한다. (`vl_grounding` 사용)
2. 우편함 창이 열리면, 우측 하단의 '일괄 수령' 또는 '모두 받기' 버튼을 찾아 클릭한다.
3. 보상 획득 팝업이 나타나면, 팝업 바깥쪽의 빈 공간이나 '확인' 버튼을 클릭하여 팝업을 닫는다.
4. 다시 우측 상단의 'X' 버튼을 눌러 우편함을 닫고 로비로 복귀한다.

# 주의사항
* 우편함 아이콘에 빨간색 점(알림)이 없더라도 일단 클릭해서 확인한다.
```

### 예시 2: 게임 스토리 스킵 (조건부 판단 포함)
```markdown
---
name: "스토리 고속 스킵"
description: "재생 중인 스토리 컷신이나 대화를 빠르게 스킵하고 넘깁니다."
triggers: ["스토리 스킵", "스킵해", "넘겨"]
---

# 목표
현재 진행 중인 스토리를 강제로 스킵하고 다음 화면(로비 또는 전투)으로 넘어간다.

# 절차
1. 화면 우측 상단에 '메뉴' 또는 'Menu' 아이콘이 보이면 클릭하여 옵션을 연다.
2. 펼쳐진 메뉴에서 'Skip' 또는 '스킵' 아이콘(보통 빨리감기 기호)을 찾아 클릭한다.
3. 화면 중앙에 "스토리를 스킵하시겠습니까?" 팝업이 나타나면, '확인' 버튼을 찾아서 클릭한다.

# 주의사항
* 화면에 메뉴 버튼이 보이지 않으면, 화면 중앙을 한 번 가볍게 클릭(`request_click`)하여 UI를 활성화시킨 뒤 1번부터 다시 시도해라.
```

### 예시 3: 알람 맞추기 (Non-Game API 연동)
```markdown
---
name: "알람 설정 템플릿"
description: "유저가 특정 시간 뒤에 알려달라고 할 때 알람을 설정하는 요령입니다."
triggers: ["알람 맞춰", "알려줘", "타이머"]
---

# 목표
유저의 요청 시간을 정확히 계산하여 알람 시스템에 등록한다.

# 절차
1. 유저의 입력 텍스트를 분석하여 정확히 몇 분/시간 뒤인지 수치(offset)를 추출한다.
2. `alarm_maker` 등의 알람 관련 툴을 호출하여 해당 시간에 알람이 울리도록 설정한다.
3. 유저에게 "알람이 설정되었습니다"라고 친절하게 대화 응답을 생성하여 알려준다.
```

## 4. 유니티 클라이언트에서의 제작(CRUD) UX 상상

유니티 클라이언트에서 이 스킬들을 편집할 때, 유저는 코드 에디터를 다루는 것이 아니라 직관적인 폼(Form)을 마주하게 됩니다.

1. **자동 요약 생성기**: "기록 시작"을 누르고 유저가 일련의 행동(메뉴 누르기 -> 스킵 누르기 -> 확인 누르기)을 완료한 뒤 "기록 종료"를 누르면, 백엔드 LLM이 그 궤적(Trajectory)을 분석하여 위 예시 같은 `SKILL.md` 초안을 자동으로 써줍니다.
2. **에디터 뷰**:
   - [이름] 텍스트 박스
   - [설명] 텍스트 박스
   - [본문 에디터] 넓은 텍스트 영역 (마크다운 지원)
3. **저장**: 유니티가 이 폼 데이터를 조합하여 `POST /skills` API를 쏘면 파이썬 서버의 `skills/` 디렉토리에 깔끔한 `.md` 파일로 저장됩니다.
