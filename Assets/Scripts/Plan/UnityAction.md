# AI 마우스 클릭 시뮬레이션 및 가짜 마우스 UI 구현 검토 보고서

현재 `ExecutorMouseAction.cs`는 `user32.dll`의 `SetCursorPos`와 `mouse_event`를 사용하여 **실제 윈도우 OS 마우스**를 물리적으로 이동시키고 클릭하고 있습니다. 이를 실제 마우스 이동 없이(또는 사용자가 느끼지 못하게) 처리하고 가짜 마우스 UI를 띄우는 방법에 대한 조사 결과입니다.

## 1. 하드웨어 마우스 이벤트 시뮬레이션의 근본적 문제

현재 `user32.dll`의 `SetCursorPos`와 `mouse_event`(또는 `SendInput`)를 사용하는 방식은 **Windows OS의 전역(Global) 하드웨어 커서**를 제어합니다.
이 방식은 모든 프로그램에서 100% 작동하지만, 커서를 순간이동 시켰다가 복귀시켜도 **사용자가 마우스 버튼을 누르고 있는 중(드래그)이거나 타이핑 중일 때 심각한 간섭(인터럽트)을 발생**시킨다는 치명적인 단점이 있습니다.

## 2. 사용자 간섭 없이 타 프로그램을 클릭하기 위한 대안 (검토)

사용자의 실제 마우스 조작(드래그 등)을 방해하지 않으면서 다른 윈도우 프로그램을 클릭하려면 다음 두 가지 접근 방식 중 하나를 선택해야 합니다.

### 대안 A. 비활성 윈도우 메시지 전송 (PostMessage / SendMessage)
실제 마우스 커서를 아예 이동하지 않고, 타겟 윈도우의 메시지 큐에 직접 마우스 클릭 신호를 쏘는 방식입니다. (일명 '비활성 매크로' 방식)

*   **구현 원리**:
    1.  `WindowFromPoint` API를 사용하여 AI가 클릭할 화면 절대 좌표(x, y) 아래에 있는 최상단 창의 핸들(HWND)을 가져옵니다.
    2.  `ScreenToClient` API를 사용해 화면 절대 좌표를 해당 창 내부의 상대 좌표로 변환합니다.
    3.  `PostMessage` 또는 `SendMessage`를 사용해 `WM_LBUTTONDOWN`(0x0201)과 `WM_LBUTTONUP`(0x0202) 메시지와 상대 좌표값을 해당 HWND로 전송합니다.
*   **장점**: 사용자의 실제 마우스 위치나 드래그 상태에 **전혀 영향을 주지 않습니다.** 완벽한 백그라운드 클릭이 가능합니다.
### 대안 C. UI Automation (UIA) API 활용 (강력 추천)
마이크로소프트의 공식 접근성(Accessibility) API인 **UI Automation**을 사용하여 화면의 특정 좌표에 있는 UI 요소(버튼, 링크 등)를 찾아내고, 마우스 대신 프로그래밍 방식으로 '실행(Invoke)' 이벤트를 트리거하는 방식입니다. 화면 읽기 프로그램(Narrator 등)이 사용하는 원리와 같습니다.

*   **구현 원리**:
    1.  `AutomationElement.FromPoint(new Point(x, y))`를 호출하여 해당 좌표의 UI 요소를 찾습니다.
    2.  해당 요소가 `InvokePattern`(클릭 가능한 버튼), `TogglePattern`(체크박스), `SelectionItemPattern` 등을 지원하는지 검사합니다.
    3.  패턴을 지원한다면 `((InvokePattern)pattern).Invoke()`를 호출하여 **백그라운드에서 즉시 실행**시킵니다.
*   **장점**: 마우스 커서를 아예 건드리지 않으므로 드래그 중이거나 타이핑 중이어도 **100% 사용자 간섭이 없습니다.** 또한 `PostMessage`가 막히는 크롬 브라우저, 디스코드, 일렉트론 앱 등 **대부분의 최신 앱에서도 완벽하게 동작**합니다.
*   **단점**: 일부 자체 엔진을 사용하는 게임(예: DirectX 커스텀 UI)에서는 UI 요소를 인식하지 못해 동작하지 않을 수 있습니다.

## 3. 결론 및 최종 하이브리드 설계안 (Plan)

가장 완벽한 사용자 경험을 위해, 실제 윈도우 클릭을 처리하는 `ExecutorMouseAction.cs`에 위에서 검토한 3가지 방식을 혼합한 **다단계 하이브리드 폴백(Fallback) 구조**를 제안합니다.

1.  **1단계: UI Automation (UIA) 시도 (최우선)**
    *   해당 좌표의 UI 엘리먼트를 찾고 `Invoke` 패턴을 지원한다면, 즉시 UIA로 백그라운드 클릭을 수행하고 종료합니다. (마우스 이동 없음, 간섭 제로, 크롬 호환)
2.  **2단계: PostMessage (비활성 클릭) 시도**
    *   UIA가 실패한 경우(예: 단순 폴더 창이나 구형 프로그램), 창 핸들(HWND)을 찾아 `WM_LBUTTONDOWN/UP`을 보냅니다. (마우스 이동 없음, 간섭 제로)
3.  **3단계: 안전한 하드웨어 클릭 (최후의 보루)**
    *   1, 2단계가 모두 실패하거나 게임 클라이언트처럼 강제적인 하드웨어 클릭이 필요한 경우만 수행합니다.
    *   `GetAsyncKeyState`로 사용자의 현재 마우스 상태를 체크하여, 조작 중(드래그)이면 대기(Queue)하고 조작이 멈추는 찰나의 순간에 하드웨어 마우스(`mouse_event`)를 순간이동시켜 클릭하고 복귀합니다.

## 2. 가짜 마우스 UI (Fake Cursor) 구현 방안

말씀하신 "가짜 마우스 UI"는 유니티 `Canvas` 최상단에 마우스 커서 이미지(Image 컴포넌트)를 띄워두고, AI가 액션을 할 때 이 UI를 애니메이션으로 이동시키는 **효과 장치(Visual Effect)**로 분리하여 구현하는 것이 가장 좋습니다.

### 구현 흐름 (AI Action 수신 시):
1.  **가짜 마우스 이동 애니메이션 (유니티 화면)**
    *   VLM 엔진에서 (x, y) 좌표를 넘겨받습니다.
    *   Coroutine의 `Vector2.Lerp`나 DOTween을 사용하여 화면상에 띄워둔 "가짜 마우스 UI 이미지"를 해당 (x, y) 좌표로 부드럽게 이동시킵니다. (예: 0.3~0.5초 소요)
2.  **도착 시 클릭 이펙트 연출**
    *   가짜 마우스가 목적지에 도달하면, 커서 이미지가 눌리는 듯한 애니메이션(Scale 축소/확대)을 재생하고, `fx_click` 파티클을 터뜨려 시각적 효과를 줍니다.
3.  **실제 클릭 처리 트리거 (백그라운드 은닉 처리)**
    *   **유니티 내부 객체 클릭 시**: `EventSystem`을 통해 실제 마우스 개입 없이 즉시 가상 클릭 이벤트를 강제 발생시킵니다.
    *   **타 윈도우 클릭 시**: 타이밍에 맞춰 OS 마우스를 해당 좌표로 순간이동시켜 `mouse_event`로 즉각 클릭하고, 원래 사용자의 마우스 위치로 다시 순간이동시킵니다. (마우스가 깜빡이는 찰나이므로 사용자는 화면상 가짜 마우스가 클릭한 것처럼 느낍니다)

## 3. 결론 및 향후 적용 방향 (Plan)

1.  **가짜 마우스 UI 프리팹 제작**: 마우스 커서 스프라이트를 포함한 UI를 최상단 캔버스에 배치하는 `FakeCursorManager`(가칭)를 구현합니다.
2.  **`ApiVlEngineManager.cs` 수정**:
    *   기존에는 좌표 수신 시 즉시 OS 클릭 이벤트를 호출했습니다.
    *   변경 후에는 코루틴을 통해 **가짜 마우스 UI가 좌표로 이동하는 애니메이션을 먼저 실행**하고, 도착 시점에 백그라운드 클릭을 수행하도록 동기화합니다.
3.  **`ExecutorMouseAction.cs` 딜레이 리팩토링 (OS 마우스 점유 최소화)**:
    *   타 프로그램 호환성을 위해 `mouse_event` Win32 API는 유지하되, `Thread.Sleep(50)`으로 인한 마우스 튀는 현상을 최소화합니다.
    *   마우스 복귀 모드(`isMouseMove=false`) 일 때, 사용자 조작 방해를 최소화하도록 초고속 복귀 구조로 다듬어 실제 마우스의 개입을 완전히 숨깁니다.
