# EquipSystem 슬롯 저작 체계 — 최종 제안

## 1. 결론 아키텍처

네 접근은 사실상 같은 뼈대(SO 템플릿 원본 + 일회성 멱등 스탬프 + 기존 클립보드 수학 재사용 + `EquipSocketEditor` 라이브 미리보기로 마감)에 수렴했고, 비판도 이 뼈대 자체는 전부 승인했다. 차이는 "본을 어떻게 찾고, 복사 경로를 몇 개 두느냐"였다. 최종안은 **원본을 `EquipSlotTemplate` SO 하나로 통일**하되, 복사를 **두 경로로 분리**한다: 같은 스켈레톤(의상 전파)은 golden-propagation의 **Donor 직접 복사**(본 이름 일치 + 본-로컬 값 무손실 복사, 가장 신뢰도 높고 60개+ 규모의 승부처), 다른 캐릭터는 **본 해석 사다리 스탬프**(이름 → Humanoid → 별칭 → 물리필터된 최근접). 저작(만들기)은 Phase 3에서 surface-click의 **표면 클릭 배치**(단, BakeMesh 규약 추측을 버리고 CPU 수동 스키닝으로)로 업그레이드한다. skeleton-landmark의 450줄 토폴로지 휴리스틱은 기각한다.

- **원본**: `EquipSlotTemplate.asset` (SO, `Editor/Templates/`에 저장 — Resources 금지). 슬롯당 slotId·부착 본 이름+별칭·Humanoid 본·**본-로컬 오프셋(높이비 스케일)**·루트-로컬 정규화 비율위치(폴백)·캡슐 높이비. "골든 캐릭터" 1명에서 Capture(slotId 기준 merge)로 만든다.
- **만들기 도구**: Phase 1~2는 기존 `Add EquipSocket To Selection` + `EquipSocketEditor` 라이브 미리보기. Phase 3에서 `Slot Author (Surface Click)` — 씬 클릭 1번으로 위치+지배 본 결정.
- **복사 도구**: `Equip Propagation` 창 하나. Donor 모드(같은 캐릭터 의상)와 Template 모드(새 캐릭터), 배치 대상 다중선택, **드라이런 기본값**, 슬롯×프리팹 리포트(해석 방법 라벨 + [열기] 버튼).
- **보호 장치**: 스탬프 시 소켓에 스냅샷(`EquipSocketStamp` 마커: 로컬 pos/rot/캡슐값)을 기록, 재스탬프 시 현재값≠스냅샷이면 손보정으로 간주해 건너뜀. 수동 lock 플래그는 두지 않는다(풋건).
- **물리 본 안전망**: MagicaCloth `serializeData.rootBones`(+SerializedProperty 전체 순회 폴백) → **자손 전체 확장** → 이름 패턴(일본어 포함)과 병행, 사다리 **전 단계 결과**와 Extract 시점 골든 소켓에도 적용.

## 2. 저작 파이프라인 (사용자 조작 기준)

### (a) 원본 만들기 — 골든 캐릭터 1명, 슬롯 3개 (프로젝트 전체 1회)
Phase 1~2 (기존 도구):
1. 프리팹 모드 진입, 본 선택 → `Add EquipSocket To Selection` → slotId 입력 → 라이브 미리보기 드래그. 슬롯당 6~10 조작(본 탐색 포함).
2. 루트 선택 → `Capture Template` → 저장. +3.
→ **합계 약 25~35 조작.** 기준선(수작업)과 같거나 약간 위 — 네 접근/비판 모두 "첫 캐릭터는 싸지지 않고, 그래도 된다"에 합의.

Phase 3 (표면 클릭 도입 후): 본 탐색(슬롯당 3~8 조작)이 씬 클릭 1번으로 대체 → **약 15~24 조작.** 클릭은 위치·본만 주므로 회전 드래그 1~2회/슬롯은 여전히 필수 공정으로 계상한다(surface-click 비판2 지적 수용).

### (b) 새 캐릭터 1명에 3슬롯 재현
1. Project에서 프리팹 선택 → Propagation 창 Template 모드 → 드라이런 리포트 확인 → 실행. **명목 2~4 조작.**
2. `NEAREST`/물리의심 플래그 슬롯만 [열기] → 라이브 미리보기 드래그. 슬롯당 +4~6.
→ **기대 5~10 조작** (비판 회계: 3슬롯 전부 무보정 통과 30~50%, hand_r은 포즈 편차로 보정 빈발). 수작업 기준선 25~33 대비 3배 이득.

### (c) 같은 캐릭터 의상 10개 전파
1. Propagation 창에 보정 완료된 베이스 프리팹을 Donor로 드래그 — 1
2. 의상 10개 다중선택 — 2 / [Stamp] — 1
→ **4 조작 + 초기 신뢰 형성기 표본 검수 2~3개(+6~9).** 같은 스켈레톤이라 본 이름 일치 + 로컬 값 그대로 복사 = 정규화 왕복 없음. 수작업 60~120 조작 대비 압도적. 60개+ 전체도 선택 단위만 커진다. Model(.fbx) 프리팹은 자동 스킵+리포트.

## 5. 단계별 구현 계획

**Phase 1 — Donor 전파 (최소 가치 증명, ~400줄, 저위험)**
- 산출물: 유틸 추출, `EquipSlotTemplate` SO+Capture(merge), `EquipSocketStamp`, Donor 직접 복사 + 배치 프리팹 IO(Model 스킵, LoadPrefabContents→SaveAsPrefabAsset→finally Unload) + 콘솔 리포트.
- 근거: 두 워크로드 비판 모두 "C(의상 전파)가 존재 이유"라 합의했고, 검증된 클립보드 수학만 쓰므로 기술 리스크 최저.
- 검증: 골든 1명을 기존 도구로 저작 → 의상 프리팹 5개에 Donor 전파 → 프리팹 열어 부모 본/위치/캡슐 월드크기 확인 → batchmode 1회로 컴파일 검증. 성공 기준: 무보정 통과율 90%+.

**Phase 2 — 크로스 캐릭터 스탬프 (~400줄)**
- 산출물: 본 해석 사다리(교정된 순서) + 본-로컬 오프셋 우선 + HintBoneOrigin 모드 + 물리 본 필터(전 단계 적용) + Propagation 창(드라이런 기본, [열기] 버튼) + 스냅샷 기반 손보정 보호.
- 검증: Generic 립 2명(스케일 35 / 20000) + Humanoid 1명에 3슬롯 스탬프, 리포트의 해석 방법 라벨과 물리 의심 플래그 정확성 확인. `diana_rigging`(BoneCloth)에서 헤어 본 회피 동작 확인, `arona`(MeshCloth, rootBones 공집합 실측)에서 이름 패턴 방어 확인.
- 사용자 Play 검증: 스탬프된 캐릭터에 hairpin 장착 후 애니메이션 재생 — 출렁임 없이 머리 추종하는지.

**Phase 3 — 표면 클릭 저작 (~500줄, 리스크 집중)**
- 산출물: 수동 스키닝 레이캐스터(백페이스 컬, 빈 bones 배열 가드) + 지배 본 결정 + 클릭 배치 창 + 표면 스냅 옵션. Esc 탈출/모드 표시 명시(배치 모드 풋건 완화).
- 검증: 스케일 1/35/20000 + 미러 스케일 립에서 클릭 히트점이 렌더 표면과 일치하는지, 왼쪽 귀 클릭이 왼쪽에 찍히는지.

**Phase 4 (선택) — 별칭 테이블 확충, 2D degrade 모드, 리포트 UX 개선.**

## 6. 리스크와 완화

- **MagicaCloth 직렬화 버전 결합**: `serializeData.rootBones` 경로는 프로젝트 소스에서 실존 확인됐으나 버전업 시 조용히 깨질 수 있음 → SerializedProperty 전체 순회 폴백 + 이름 패턴(일본어 포함) 상시 병행, 리포트에 "물리 본 의심" 플래그.
- **MeshCloth 시각 분리**: 정점 시뮬 헤어에 정적 본 부착 시 헤어핀이 머리카락과 분리돼 보임 → 스냅 대상이 `sourceRenderers`에 속하면 경고 1줄(해결이 아니라 고지).
- **hand_r 포즈 편차**: 자동으로 완전 해결 불가 — HintBoneOrigin + "검수 필수" 라벨로 보정을 워크플로우에 내장.
- **조용한 오배치**(성공 리포트인데 틀림): 드라이런 기본값 + 캐릭터별 그룹 실행 권장 + 초기 표본 검수를 조작 예산에 공식 포함.
- **실패 시 하한**: 모든 경로가 실패해도 결과물은 평범한 GO+EquipSocket이라 기존 수동/클립보드 워크플로우로 무손실 하차 — 기준선 밑으로 뚫리는 실패 모드 없음(양쪽 비판 공통 확인).
- **2D 캐릭터**: 본 추종 불가가 정의상 한계. 루트 부착까지만 지원하고 리포트에 명시.

## 7. 사용자가 결정해야 할 것

1. **골든 캐릭터를 누구로 할 것인가?** 추천: Generic 립 중 가장 표준적인 Bip001 캐릭터(다수파와 같은 계열이라 별칭 명중률 최대). Humanoid 커스텀은 `GetBoneTransform`으로 어차피 결정적이라 골든이 아니어도 됨.
2. **hairpin을 물리 헤어 본에 붙이는 옵션을 열어둘 것인가?** 기본은 물리 본 회피(head 승격)를 추천하되, 슬롯별 `avoidPhysicsBones` 토글을 두는 안. "일부러 흔들리는 머리카락에 달고 싶은" 연출이 필요하면 토글 OFF + 수동 부모 지정.
3. **Phase 3(표면 클릭)를 정말 만들 것인가?** 추천: Phase 2까지 써본 뒤 결정. 신규 저작이 캐릭터 25명에서 대부분 끝나 있으면(=만들기보다 복사가 남았으면) 500줄 투자 대비 이득이 작을 수 있음. 신규 캐릭터 유입이 계속되면 착수.
4. **드라이런을 기본값으로 유지할 것인가?** 추천: 초기 10회는 드라이런 기본, 신뢰 형성 후 창 설정으로 즉시 실행 전환 가능하게. 검수 비용(초기 프리팹 2~3개 열어보기)은 없앨 수 없는 실비용으로 인정하고 시작하는 것을 권장.
