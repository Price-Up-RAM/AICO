# Plan4-1: Unity 클라이언트 스킬/룰 관리 UI 명세서

본 문서는 파이썬 서버에서 사용할 마크다운(Markdown) 기반의 `SKILL.md` 및 `RULE.md` 파일들을 유니티(Unity) 클라이언트에서 직접 생성하고 관리하기 위한 **스킬 관리 화면(UI/UX) 설계 및 개발 가이드**입니다. 유니티 개발 파트에 전달될 목적으로 작성되었습니다.

---

## 1. 개요 및 목적

*   **배경**: AI 에이전트의 환각(Hallucination)을 방지하고 유저가 원하는 정확한 동작을 수행하기 위해, 행동 지침(Skill)과 판단 기준(Rule)을 유저가 직접 정의하고 관리해야 합니다.
*   **포맷**: 모든 데이터는 파이썬 서버에 Markdown 파일(`.md`)로 저장되며, 상단의 메타데이터(YAML Frontmatter)와 하단의 본문(자연어 지침서)으로 구성됩니다.
*   **목적**: 유니티 클라이언트 내에 이를 직관적으로 관리(CRUD)할 수 있는 전용 관리창(Skill Manager UI)을 구현합니다.

---

## 2. 핵심 UI/UX 플로우

스킬 관리 화면은 크게 **목록 화면(List View)**, **편집 화면(Editor View)**, 그리고 **자동 생성 플로우(Auto-Recorder)** 세 가지로 나뉩니다.

### 2-1. 스킬/룰 목록 화면 (List View)
현재 서버에 저장된 모든 스킬과 룰을 한눈에 보고 관리하는 대시보드입니다.

*   **Data Fetching**: 화면 진입 시 파이썬 서버의 `GET /skills` API를 호출하여 목록을 갱신합니다.
*   **표시 항목**: 
    *   스킬 이름 (`name`)
    *   간략한 설명 (`description`)
    *   트리거 키워드 태그 (`triggers`)
*   **기능 버튼**:
    *   `[새 스킬 작성]` (빈 에디터 화면으로 이동)
    *   `[동작 녹화로 만들기]` (자동 생성 플로우로 이동)
    *   개별 아이템의 `[수정]`, `[삭제]` 버튼 (`DELETE /skills/<name>` 연동)

### 2-2. 스킬 편집 화면 (Editor View)
마크다운 포맷을 유저 친화적인 Form 형태로 감싸서 제공하는 에디터입니다.

*   **메타데이터 입력 영역 (Frontmatter 대응)**:
    *   `[이름]` (Input Field): 스킬의 고유 명칭
    *   `[설명]` (Input Field - Multiline): 이 스킬의 목적 요약
    *   `[트리거 키워드]` (Tag Input): 유저 발화 중 이 스킬을 발동시킬 키워드들 추가/삭제
*   **본문 입력 영역 (Body 대응)**:
    *   `[상세 지침서]` (Text Area - 넓은 영역): 자연어 형태의 행동 절차 및 주의사항 입력. (기본적인 마크다운 구문 하이라이팅이 지원되면 좋음)
*   **기능 버튼**:
    *   `[저장]`: 입력된 폼 데이터를 조합하여 `POST /skills` 또는 `PUT /skills/<name>` API로 전송.

### 2-3. 동작 녹화 기반 자동 생성 (Auto-Recorder Flow)
유저가 직접 텍스트를 치는 수고를 덜기 위한 보조 편의 기능입니다. **(단순 매크로 용도)**
> 💡 **설계 주의사항**: 이 자동 요약 기능은 `diff_compare` 대기 같은 복잡한 조건부 행동이나 분기를 완벽히 추론해내지는 못합니다. 기껏해야 "버튼 3번 누르기" 같은 단순하고 짧은 행동(3-step 내외)을 마크다운 초안으로 잡아주는 역할로 한정합니다. 복잡한 룰이나 대기 조건은 유저가 에디터에서 직접 작성합니다.

1.  **녹화 시작**: 유니티 화면 어딘가에 떠 있는 UI에서 `[기록 시작]` 버튼 클릭.
2.  **행동 궤적 수집**: 유저가 유니티 클라이언트 내에서 특정 동작들(특정 메뉴 클릭, 특정 좌표 클릭, 창 닫기 등)을 수행합니다. 유니티는 이 이벤트 로그(Trajectory)를 임시 배열에 누적합니다.
3.  **녹화 종료 및 요약 요청**: `[기록 종료]` 버튼을 누르면, 누적된 로그를 파이썬 서버의 전용 엔드포인트(예: `POST /skills/summarize`)로 전송합니다.
4.  **에디터 진입**: 서버의 LLM이 로그를 분석하여 자연어 절차서(Markdown Body)로 변환해 응답하면, 이 텍스트가 채워진 상태로 **스킬 편집 화면(Editor View)**이 열립니다.
5.  유저는 요약된 내용을 검토 및 약간의 수정 후 `[저장]`합니다.

## 3. 파이썬 서버 연동 명세 (API 연동 가이드)

유니티 클라이언트의 UI 액션은 다음의 파이썬 API들과 연동되어야 합니다.

| 액션 | 메서드 | 엔드포인트 (가칭) | 전송 데이터 (Payload) | 설명 |
|---|---|---|---|---|
| 목록 갱신 | `GET` | `/skills` | 없음 | 전체 스킬의 메타데이터 목록 반환 |
| 상세 조회 | `GET` | `/skills/{name}` | 없음 | 특정 스킬의 본문 텍스트 포함 반환 |
| 스킬 생성 | `POST` | `/skills` | `name`, `description`, `triggers`, `body` | 새로운 .md 파일 생성 |
| 스킬 수정 | `PUT` | `/skills/{name}` | `description`, `triggers`, `body` | 기존 .md 파일 덮어쓰기 |
| 스킬 삭제 | `DELETE`| `/skills/{name}` | 없음 | .md 파일 삭제 |
| 자동 요약 | `POST` | `/skills/summarize`| `action_logs` (JSON 배열) | 로그를 LLM이 마크다운 본문으로 요약하여 반환 |

---

## 4. UI/UX 디자인 고려사항 (Design Checklist)

*   [ ] **직관성**: 유저는 백엔드에서 Markdown으로 저장되는지 YAML이 쓰이는지 알 필요가 없습니다. 일반적인 설정 창이나 메모장 앱처럼 친숙한 UI여야 합니다.
*   [ ] **인게임 오버레이**: 게임이나 주 사용 화면을 완전히 가리지 않고, 투명도가 있는 패널이거나 팝업 창 형태로 띄워 행동을 녹화할 때 방해되지 않아야 합니다.
*   [ ] **피드백**: 저장 완료, 삭제 확인, 요약 중(로딩 스피너) 등의 상태 피드백이 명확해야 합니다.
