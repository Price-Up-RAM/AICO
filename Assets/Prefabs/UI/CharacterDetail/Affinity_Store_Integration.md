# Affinity(인연도) × 상점 연동 — 책임 이관 문서

> 상태: **문서 단계 — 코드 수정 없음.** 2026-07-11 신설. 인연도-상점 연동 설계의 책임(오너십)을
> **Store 폴더 → CharacterDetail 폴더로 이관**하며 만든 오너 문서.
> 인연도 시스템 본체 계획: 같은 폴더의 `Affinity_Plan.md` (구 Relationship_Plan.md — 상점/재화 장을 이 문서로 이관).

> 용어: 인연도의 영문/코드 용어는 **affinity** (구 계획의 relationship 표기는 폐기 — "relationship"은
> 향후 다른 시스템의 예약어이므로 인연도 코드/에셋/필드/문서 용어로 사용 금지). 한국어 명칭 "인연도"는 유지.

## 1. 배경 / 소유권

- Store 프로토타입(`Assets/Prefabs/UI/Store` — README.md, WORKLOG.md, Store_Design.md)은
  인연도 재화 루프 검증용으로 만들어졌고, 인연도 연동 관련 "남은 일"이 Store 문서들에 흩어져 있었다.
- **이 문서가 인연도-상점 연동 설계의 단일 출처(single source)다.**
  - Store 폴더의 문서는 이제 상점 프로토타입 자체(UI/카탈로그 3계층/판매 프로토콜/프리뷰 파이프라인)의
    **기술 문서**로 남는다.
  - 인연도 연동 설계(선물 → 포인트, 단계 한정 상품, 재화/경제 구조 등)는 **여기서 관리**한다.
- 인연도 시스템 본체(레벨 모델·단계 명칭·레벨업 보상·호감도 잔재 제거)는 `Affinity_Plan.md` 소관.
  이 문서는 그중 상점/재화와 맞닿는 부분만 다룬다.

## 2. Store 프로토타입이 이미 검증한 것

Store 프로토(구현 완료, 플레이 검증됨)가 인연도 연동의 기반으로 이미 깔아둔 것:

- **지갑**: 기존 미션 재화 시스템 `InventoryManager`(Prefabs/UI/Mission)의 **Gold**를 그대로 사용
  (`AddGold`/`SpendGold`/`InventoryChanged`). 새 지갑을 만들지 않는다는 원칙이 실증됨.
- **구매/판매 루프**: 카드 클릭 → 확인 모달(수량 "n / max" + 최종금액) → `SpendGold` →
  `AddToMain`(실패 시 전액 환불). 판매는 인벤토리 슬롯 → 판매 존 드래그 → 모달 → `ExecuteSale`
  (판매가 = 구매가의 50%, 카탈로그 밖 10G).
- **선물 태그 3종**: `gift_s` "선물(소)" 50G(+10) / `gift_m` "선물(중)" 120G(+30) /
  `gift_l` "선물(대)" 300G(+100) — 가격과 인연도 상승량까지 데이터로 등록됨.
- **`StoreEntry.giftPoints` 필드 준비됨**: 선물 계열의 증정 시 인연도 상승량. 0이면 일반 상품.
  지급 로직만 없을 뿐 데이터 파이프는 완성.
- **카드 표기**: 선물 카드에 `CardSub` "친밀도 +N" 표기 — **"인연도 +N"으로 표기 통일은 이 문서의
  할 일(3장 ⑤)**.
- **미션 보고**: 구매 키의 소속 태그가 "장착물"이면 `MissionList.Report("AF0005", 수량)`
  (액세서리 구매하기) 호출. CH0007(골드 소비)은 `SpendGold` 내부 집계로 자동 진행.

## 4. 재화/경제 설계 (구 플랜 5장 이동)

### 4.1 기존 코드에 이미 깔려 있는 전제

Mission 시스템이 상점 경제를 이미 전제하고 있다 — 여기서 출발하는 게 자연스럽다:

- `MissionReward`에 **`gold` + `item1`/`item2`/`item3`** 필드 존재 (아이콘만 있고 정체 미정의 플레이스홀더).
- `CH0007` "골드 소비하기"(100/1000/5000), `CH0008` "아이템 모으기"(5/20/50), `AF0005` "액세서리 구매하기"(5/15/30) — **소비·수집·구매** 미션이 이미 정의됨.
- ✅ **검증됨**: CH0007은 `SpendGold` 내부 집계로, AF0005는 장착물 태그 구매 시 `MissionList.Report`로
  프로토 상점에서 이미 실동작한다 (2장).

### 4.2 재화 구조 (안)

| 안 | 구조 | 평가 |
|---|---|---|
| 단일 재화 (권장 시작점) | **Gold** 하나로 통일 | 단순. 밸런싱 부담 최소. item1~3은 재화가 아닌 소모품으로 |
| 이중 재화 | Gold(일반) + 크리스탈(희소) | 희소 재화로 한정 상품 구분 가능하나, 무과금 단일 앱에서 이중 재화는 과설계 위험 |

- ✅ **검증됨**: 프로토 상점은 단일 Gold(`InventoryManager`)로 구매·판매·환불까지 완주 — 단일 재화안의
  실효성은 확인됨. 확정은 미결(5장).
- **획득처(소스)**: 미션 보상(이미 gold 정의됨), 인연도 레벨업, 일일 출석, 대화 보너스, 알람/생산성 기능 사용
- **소비처(싱크)**: 상점 구매(치장 4종), 선물 구매, (미결) 이름 변경권 등

### 4.3 상점 구성 (안)

- **판매 카테고리**: 장착물 / 포즈 / 이펙트 / 선물 / 잡화 — 프로토 상점 탭 5종(슬롯 6개 중 예비 1).
  ✅ **검증됨**: 태그 레지스트리 기반 탭 5종 + 예비 슬롯 1이 프로토에 구현됨(상품 합계 16종).
  **의상은 캐릭터별로 판매 내용이 바뀌는 카테고리라 보류**(캐릭터 컨텍스트 설계 후 예비 슬롯에 추가).
- **선물 시스템 (강력 추천)**: 상점에서 선물 구매 → 캐릭터에게 증정 → **인연도 포인트 획득**.
  Gold의 소비처와 인연도의 획득처를 동시에 해결하는 연결고리. 경제 루프가 닫힌다:
  ```
  활동(대화·미션·알람) → Gold 획득 → 상점(선물·치장 구매)
        ↑                                    │
        └── 레벨업 보상(Gold·장신구·해금) ← 인연도 상승 ←┘ (선물 증정)
  ```
  ✅ **검증됨(절반)**: 선물 구매(gift_s/m/l, giftPoints 데이터)까지는 프로토가 구현. 증정 UX와
  포인트 지급이 남은 절반 (3장 ①).
- **인연도 단계 한정 상품**: 특정 단계 이상에서만 구매 가능한 상품(예: Lv.6+ 전용 의상) — 인연도에 상점 외적 가치 부여. (3장 ②)
- **로테이션/한정**: 일일 or 주간 로테이션 상점. 초기엔 고정 진열로 시작해도 됨. (3장 ④ / 5장 미결)

### 4.4 판매(되팔기) 계열

- **치장류(장착물/의상/포즈/이펙트)는 1회 구매 영구 해금** → 되팔기 대상에서 제외 권장 (중복 구매 자체를 막는 편이 단순).
- 되팔기가 필요한 건 **수량형 아이템**(선물, 소모품)뿐 — 구매가의 50% 환급 정도.
  ✅ **검증됨**: 프로토 판매 존이 구매가 50% 환급(카탈로그 밖 10G)으로 구현됨. 단 현재는 치장류도
  수량형으로 팔리는 프로토 단순화 상태 — "영구 해금 + 중복 구매 차단"은 미구현.
- EquipSystem 아이템을 수량형으로 갈 경우에만 되팔기 유의미. 인연도 보상 전용 장신구는 판매 불가 처리. (3장 ③ — `sellable` 플래그)

### 4.5 item1~3 정체 후보 (미결)

1. 선물 3등급 (소/중/대 — 인연도 포인트 +10/+30/+100)
2. 상자/티켓 (치장 랜덤 or 선택권)
3. 강화·제작 재료 (EquipSystem 확장 대비)

→ 인연도와의 시너지는 1안(선물 3등급)이 가장 깔끔.
✅ **참고**: 프로토 상점의 선물 태그 3종(gift_s/m/l — +10/+30/+100)이 1안과 정확히 같은 등급 구조로
이미 등록되어 있어, 1안 채택 시 `MissionReward.item1~3` ↔ gift_s/m/l 매핑만 확정하면 된다.

## 5. 미결정 사항 (구 플랜 7장의 4·5·6 이동)

1. **재화 구조 확정** — 단일 Gold vs 이중(Gold+크리스탈). 단일 권장 (프로토가 단일 Gold로 검증 완료, 4.2장).
2. **`MissionReward.item1~3` 정체 확정** — 선물 3등급안 권장 (프로토 gift_s/m/l과 구조 일치, 4.5장).
3. **선물 시스템 채택 여부 및 상점 UI 스코프** — 선물 증정 UX(진입점/연출)와
   고정 진열 vs 로테이션 (3장 ①·④, 4.3장).
